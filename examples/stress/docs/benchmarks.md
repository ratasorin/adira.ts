## Source provenance

The [fusion audit](../reports/reduction-fusion-paired/audit.json) checks source hashes and captured module hashes. The original report paths predate the current folder structure. The [navigation map](../README.md#where-to-start) points to the current implementations.

Two additional archives preserve compiled artifacts that were still present when the example was reorganized:

- [Pre-organization runtime](../reports/snapshots/pre-organization-runtime.tar.gz): old flat compiled server files, including the pre-metrics and pre-fusion demo modules.
- [Historical readers](../reports/snapshots/historical-readers.tar.gz): captured numeric and fusion reader modules plus the old fusion manifest.

These are the surviving runtime snapshots, not a complete source checkout for every historical stage. Historical scripts and absolute module paths describe their original environment. The supported runners are [run.ts](../harness/benchmarks/run.ts) and [fusion.ts](../harness/benchmarks/fusion.ts); current invocation and baseline capture are in [HANDOFF.md](../HANDOFF.md#benchmarks).

## Reading the numbers

Compare before/after within the linked experiment. Changes span planner behavior, library reduction strategies, and application-owned MongoDB queries; the stages cannot be added into one isolated framework speedup. The numeric paired experiment uses direct executor calls; the main reports use HTTP. The larger fulfillment batch is a separate application implementation.

The native implementation is faster in the recorded comparisons. Regressions and preliminary trials remain in the archive. The measurements use warm caches on a local machine with a shared Node process/database pool; small samples and machine load limit tail-latency conclusions. Summed MongoDB command durations can overlap.
