## What the application establishes

- A single Adira resource can support directory, financial, service-risk and deeply nested account views through different frontend queries. The reference backend implements separate fixed views and manually chooses which reads to perform.
- Native field producers disappear when unused. The directory request runs no field callbacks and one database command in the smoke integration check.
- Computations compose across raw native blocks, native expressions, prebuilt reductions, custom batch loaders and JavaScript fields. The frontend can filter/order by application-computed values and change nested include shapes.
- Independently implemented query strategies produce exactly equal selected JSON, including child ordering, null relations and computed values, in both smoke tenants and the first/last medium tenants. Every measured response is checked against its preflight digest.
- Soft-deleted related products require nullable public product relations. Declaring them non-null would incorrectly turn a legitimate historical order into a response-validation failure.

## Main pain points exposed

These describe the initial implementation. The follow-up comparisons above measure predicate placement, display pagination, and index-access changes separately; the remaining execution-strategy costs still matter.

1. **Pruning is not scheduling.** The native finance producer is omitted from the directory view, but runs in its registered native-prefix position whenever a requested output depends on it. For a display-only account summary this still puts financial lookups before the root page. The reference backend pages first, then batches only those accounts. For computed filtering/sorting, the reference first narrows candidates by indexed base fields and groups their data in bulk. The current Adira plan does not perform those rewrites.
2. **One aggregate can do much more work than several queries.** The finance producer performs correlated order and cost lookups per candidate account. The reference groups matching data for an ID set in bulk. Driver command counts do not measure lookup iterations, documents examined or planner efficiency; inspect the saved root executionStats and code together.
3. **Different relations and execution contracts retain separate reads.** Consecutive compatible native scalar reductions now fuse. Ticket count, late-shipment count, custom exposure, manager portfolios and nested includes still have distinct inputs or strategies. `resolveBatch` lets application code deduplicate manager IDs and share a custom aggregation within each callback; it does not provide request-wide caching.
4. **Application filtering/order needs complete candidates.** Risk and days-of-cover sorting cannot safely page before calculating those fields. Native prefilters, materialized/indexed read models, equivalent native expressions or a query-aware provider are possible optimizations; silently paginating first would change answers.
5. **Candidate budgets are visible product behavior.** The whale-account history diagnostic compares a conventional complete-history calculation with an Adira complete relation capped at 400 candidates. It reports the actual cardinality and any `ReadBudgetError`. The normal comparison scenarios stay within their declared budgets; an explicit error is not treated as successful throughput.
6. **There is still a large type/configuration surface.** Relations need resource bindings even when a particular scenario only wants an aggregate. Separate mini-resources avoid recursive account/order contracts. `requires`/`provides` preserve intermediate inference, but raw Mongo stage paths and preservation semantics remain developer promises. No production guarantee is inferred from a successfully compiled pipeline.
7. **Frontend package consumption needs attention.** The shared CommonJS core required explicit conversion in the Vite workspace build. The example's frontend type checks work without backend imports, but the public contract is shared source; independent generated-package release compatibility still needs its own fixture matrix.

Separate local compiler diagnostics are saved in [typecheck-server.txt](../../reports/local-medium/typecheck-server.txt) and [typecheck-frontend.txt](../../reports/local-medium/typecheck-frontend.txt). The server project took 8.93 seconds total (7.06 seconds checking), approximately 514 MB compiler memory, and 281,564 type instantiations; the frontend took 1.93 seconds and approximately 118 MB. These measurements include the application's dependencies, including Mongoose on the server. They do not isolate Adira's contribution or measure incremental editor latency.

The [browser check](../../reports/local-medium/browser-check.json) exercised all six populated dashboards with matching data, the plan inspector and record drawer. Desktop/mobile screenshots are saved alongside it. Chrome reported no JavaScript exceptions, and the mobile document width matched its 430-pixel viewport. Those are UI checks performed after the timing run, not extra benchmark samples.

These findings depend on the source definitions used here. They do not prove that every Adira implementation must have the same performance. For example, replacing display-only correlated producers with a well-designed batch loader is a backend option. Its ergonomics and effect on computed filtering would need a separate measured variant, not an assumption that it resolves every case.

## What to change next

Conservative predicate pushdown, scheduling an eligible native display suffix after pagination, index-compatible base/policy predicates, eligible bulk count/numeric execution and compatible native scalar fusion are implemented. The demo explicitly batches revenue, cost and stock queries through typed providers. Opaque or stream-wide operations remain boundaries. Independent load scheduling, broader demand reuse and better nested include strategies remain candidates. Keep this corpus as a correctness oracle: result and ordering parity must survive every optimization.

Do not infer production readiness from this lab. It does not exercise authentication, permission revocation, transaction snapshots during concurrent writes, remote services, SQL sources, network faults, TLS, independent frontend releases, or fleet-wide load. The static 90-day finance window also avoids the unresolved design of schema-approved per-field arguments.
